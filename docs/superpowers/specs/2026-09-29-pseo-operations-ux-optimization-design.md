# pSEO 실적 대시보드 운영 안정성·사용성 최적화 설계

작성일: 2026-09-29
대상 저장소: `ryunj/LF_pSEO`

## 1. 목적

현재 pSEO 실적 대시보드의 집계 기준과 화면 구조는 유지하면서, 반복적인 데이터 갱신과 복구를 비개발자도 안전하게 수행할 수 있도록 운영 흐름을 개선한다.

이번 작업의 핵심은 다음과 같다.

- CSV와 Excel 업로드 결과를 즉시 확인할 수 있게 한다.
- 업로드 실패·부분 반영·무시된 행을 구분해 알려준다.
- 마지막 정상 데이터를 자동 보관하고 사용자가 직접 내려받거나 복원할 수 있게 한다.
- 데이터 기준일, 기간, AF 코드 매칭 현황을 첫 화면에서 확인할 수 있게 한다.
- 실제 `.xlsx` 파일을 내보낼 수 있게 한다.
- 넓은 표와 작은 화면에서도 헤더와 기준 열을 놓치지 않게 한다.
- 사용자가 선택한 필터와 보기 상태를 다음 실행 때 복원한다.

## 2. 범위

### 포함

1. 상단 데이터 상태 영역
2. 데이터 갱신 모달과 파일별 처리 로그
3. 적용 전 변경 요약 및 명시적 적용 단계
4. 자동 백업과 수동 백업 관리
5. 드래그 앤 드롭 업로드 안내
6. 화면 내 성공·주의·오류 메시지
7. 실제 `.xlsx` 내보내기
8. 표의 고정 헤더·고정 첫 열·모바일 가로 스크롤 개선
9. 빈 데이터·부분 데이터·잘못된 파일·저장소 사용 불가 상태 분리
10. 필터와 보기 선택값의 브라우저 저장

### 제외

- Gemini 등 외부 AI 기능
- 메모·협업 기능
- 첫 구매 대시보드 전용 상품 드릴다운
- 서버 데이터베이스나 로그인 시스템 도입
- 기존 PV·UV 산식, 일자 집계, 주차 표기, AF 코드 매칭 규칙 변경

## 3. 설계 원칙

- 기존 단일 HTML 중심 구조와 오프라인 사용성을 유지한다.
- 파일을 읽었다는 사실과 실제 데이터에 적용했다는 사실을 구분한다.
- 새 데이터가 유효하지 않으면 현재 정상 데이터를 덮어쓰지 않는다.
- 오류는 사용자가 다음 행동을 결정할 수 있는 문장으로 표시한다.
- 핵심 지표와 데이터 신뢰 상태를 화면 상단에서 함께 확인할 수 있게 한다.
- 기능을 늘리더라도 기본 화면은 간결하게 유지하고, 세부 로그는 모달 안에서 제공한다.

## 4. 사용자 흐름

### 4.1 첫 실행

1. 대시보드에 포함된 기본 데이터를 표시한다.
2. 브라우저에 마지막 정상 백업이 있으면 백업의 생성 시각과 데이터 기간을 비교한다.
3. 백업이 기본 데이터보다 최신이면 이를 복원하고 화면 상단에 복원 사실을 알린다.
4. 브라우저 저장소를 사용할 수 없으면 기본 데이터로 계속 동작하되 자동 백업이 비활성화되었음을 알린다.

### 4.2 데이터 갱신

1. 사용자가 `데이터 갱신` 버튼을 누르거나 파일을 화면에 끌어 놓는다.
2. 갱신 모달에서 CSV, XLSX, XLSM, XLS 파일을 선택한다.
3. 각 파일별로 파일명, 형식, 선택된 시트, 읽은 행 수, 유효 행 수, 제외 행 수, 오류를 표시한다.
4. 전체 파일 처리가 끝나면 적용 전 요약을 표시한다.
   - 적용 가능한 총 행 수
   - 데이터 날짜 범위
   - 신규·중복·제외 행 수
   - 인식된 AF 코드 수와 미매칭 코드 수
5. 치명적 오류가 없을 때만 `적용` 버튼을 활성화한다.
6. 적용 직전의 정상 데이터를 자동 백업한다.
7. 새 데이터를 적용하고 차트, 표, 상태 영역을 한 번에 다시 그린다.
8. 적용 결과를 화면 내 메시지와 모달 로그에 남긴다.

### 4.3 백업 관리

- 정상 적용이 끝날 때 현재 데이터를 마지막 정상 백업으로 저장한다.
- 사용자는 백업 관리 메뉴에서 다음 작업을 할 수 있다.
  - 현재 데이터 백업 파일 내려받기
  - 백업 파일 불러오기
  - 브라우저의 마지막 정상 백업 복원
  - 브라우저 백업 초기화
- 초기화는 되돌릴 수 없다는 설명과 확인 단계를 거친다.
- 백업 파일에는 스키마 버전, 저장 시각, 데이터 기간, 원본 행, AF 코드 매핑 정보를 포함한다.

## 5. 화면 구성

### 5.1 데이터 상태 영역

기존 상단 조작 영역 가까이에 작은 상태 카드 또는 한 줄 요약을 둔다.

- 데이터 기준일
- 포함 기간
- 정상 데이터 행 수
- 매칭된 AF 코드 수 / 미매칭 코드 수
- 마지막 갱신 시각
- 데이터 출처: 기본 데이터, 업로드, 자동 복원 중 하나

상태는 정상, 주의, 오류의 세 단계로 표현하되 색상에만 의존하지 않고 아이콘과 문구를 함께 사용한다.

### 5.2 갱신 모달

모달은 기본 화면을 복잡하게 만들지 않으면서 다음 네 구역을 제공한다.

1. 파일 선택 및 드롭 영역
2. 파일별 처리 결과 목록
3. 적용 전 변경 요약
4. `취소`와 `적용` 버튼

파일별 결과는 접을 수 있게 하며, 성공한 파일이 많을 때도 화면을 과도하게 차지하지 않게 한다. 오류가 있는 파일은 자동으로 펼친다.

### 5.3 메시지

브라우저 `alert` 사용을 제거하고 다음 형태로 통일한다.

- 짧은 성공 알림: 일정 시간이 지나면 사라지는 토스트
- 주의 또는 복구 안내: 상단 배너
- 파일별 상세 오류: 갱신 모달 내부
- 데이터가 전혀 없는 경우: 차트와 표 대신 빈 상태 안내 및 갱신 버튼

### 5.4 차트와 표

- 기존 차트 크기와 3열을 고려한 폭 정책을 유지한다.
- 화면 폭이 좁아지면 차트 카드가 자연스럽게 줄바꿈되도록 한다.
- 표 헤더는 세로 스크롤 시 고정한다.
- 첫 번째 기준 열은 가로 스크롤 시 고정한다.
- 작은 화면에서는 표를 축소해 깨뜨리지 않고 가로 스크롤을 제공한다.
- 고정 영역이 겹치지 않도록 배경색과 쌓임 순서를 명시한다.

## 6. 데이터 처리 규칙

### 6.1 지원 형식

- CSV: UTF-8 및 일반적인 한글 CSV 인코딩을 순차적으로 판별한다.
- Excel: XLSX, XLSM, XLS를 지원한다.
- 여러 파일을 한 번에 선택할 수 있다.
- Excel에서는 `PSEO` 이름의 시트를 우선하고, 없으면 필수 열을 가장 많이 가진 시트를 선택한다.

### 6.2 날짜가 없는 파일

날짜 열이 없다는 이유만으로 업로드 전체를 실패시키지 않는다.

- 날짜가 있는 행은 기존 일자·주차 집계에 포함한다.
- 날짜가 없지만 페이지·업로드 차수·AF 코드 등 다른 유효 정보가 있는 행은 해당 정보를 사용하는 비기간 집계에 포함할 수 있다.
- 기간 차트에는 날짜가 있는 행만 사용하고, 제외된 행 수를 갱신 요약에 표시한다.
- 날짜가 필요한 지표와 필요하지 않은 지표를 명시적으로 분리한다.

### 6.3 AF 코드 매칭

- 업로드 데이터의 AF 코드는 Google Sheet의 `매체코드명(NBOS등록)` 기준과 매칭한다.
- 공백, 대소문자, 숫자·문자 표현 차이를 정규화한 뒤 비교한다.
- 원본 AF 코드와 매칭된 명칭을 모두 보존한다.
- 미매칭 코드는 임의로 버리지 않고 별도 집계와 갱신 로그에 표시한다.
- Google Sheet를 브라우저에서 매번 직접 읽지 않고, 검증된 매핑 스냅샷을 대시보드 데이터와 함께 관리한다.

### 6.4 중복과 병합

- 이번 최적화의 기본 갱신 방식은 기존 동작과 동일한 전체 교체로 한다.
- 여러 파일을 한 번에 올린 경우 파일 간 동일 레코드는 정규화된 키로 중복 제거한다.
- 중복 판단 키를 만들 수 없는 행은 원본 순서를 유지하고 중복으로 간주하지 않는다.
- 향후 누적 병합 기능을 추가할 수 있도록 갱신 결과 구조에 `신규`, `중복`, `제외` 수치를 둔다. 이번 범위에서는 `신규`가 적용 가능한 전체 행 수를 의미한다.

### 6.5 유효성 검사와 원자적 적용

- 파일 읽기, 열 매핑, 행 정규화, 지표 계산을 임시 데이터에서 먼저 수행한다.
- 필수 구조를 전혀 찾을 수 없거나 유효 행이 0개면 적용하지 않는다.
- 일부 행만 잘못된 경우 정상 행은 적용 가능하게 하고 제외 사유와 수량을 표시한다.
- 적용 중 예외가 발생하면 이전 데이터와 화면 상태를 유지한다.

## 7. 저장 구조

### 7.1 IndexedDB

대용량 원본 데이터와 마지막 정상 백업을 저장한다.

- 저장 데이터: 원본 행, 정규화 결과, AF 매핑 스냅샷, 메타데이터
- 메타데이터: 스키마 버전, 저장 시각, 기준일, 기간, 행 수, 출처
- 스키마가 바뀌면 버전을 검사하고 호환 가능한 경우에만 복원한다.
- 손상되거나 호환되지 않는 백업은 자동 적용하지 않고 사용자에게 알린다.

### 7.2 localStorage

용량이 작은 사용자 보기 상태만 저장한다.

- 선택한 기간
- 비교 기간 표시 여부
- 표 필터와 정렬
- 펼침·접힘 상태 중 재사용 가치가 있는 항목

저장된 값이 현재 데이터 범위를 벗어나면 안전한 기본값으로 되돌린다.

## 8. 내보내기

- 현재 HTML 표를 확장자만 `.xls`로 저장하는 방식을 제거한다.
- 포함된 SheetJS 라이브러리로 실제 `.xlsx` 워크북을 생성한다.
- 사용자가 보고 있는 필터 상태를 반영한 시트와 전체 데이터 시트를 구분해 담는다.
- 파일명에는 대시보드명과 내보낸 날짜를 포함한다.
- 한글 열 이름, 날짜, 숫자 형식을 Excel에서 정상적으로 인식하도록 셀 타입을 지정한다.

## 9. 오류·상태 정의

| 상태 | 화면 처리 | 데이터 보존 |
|---|---|---|
| 기본 데이터 정상 | 정상 상태 표시 | 기본 데이터 사용 |
| 최신 백업 자동 복원 | 복원 안내 배너 | 백업 데이터 사용 |
| 일부 행 제외 | 주의 상태와 제외 내역 표시 | 정상 행만 적용 가능 |
| 파일 전체 오류 | 모달에 원인과 해결 방법 표시 | 기존 데이터 유지 |
| 유효 행 0개 | 적용 버튼 비활성화 | 기존 데이터 유지 |
| IndexedDB 사용 불가 | 백업 비활성 안내 | 현재 세션 데이터 유지 |
| 손상·구버전 백업 | 자동 복원하지 않고 경고 | 기본 또는 현재 데이터 유지 |
| 화면 재계산 실패 | 오류 안내와 복구 동작 제공 | 직전 정상 데이터 유지 |

## 10. 접근성·반응형 기준

- 모든 버튼은 키보드로 이동하고 실행할 수 있어야 한다.
- 모달이 열리면 포커스를 모달 안에 유지하고 닫을 때 원래 버튼으로 돌려준다.
- 상태색에는 텍스트 또는 아이콘을 함께 사용한다.
- 파일 드롭 영역은 클릭 파일 선택도 동일하게 지원한다.
- 360px 수준의 작은 화면에서도 핵심 버튼과 상태 문구가 잘리지 않아야 한다.
- 넓은 표는 가로 스크롤을 허용하되 고정 첫 열로 현재 행의 기준을 식별할 수 있어야 한다.

## 11. 검증 기준

### 자동 검증

- 기존 PV·UV, 일자·주차 집계, AF 매핑 테스트가 계속 통과한다.
- CSV와 각 Excel 형식의 정상·부분 오류·전체 오류 사례를 테스트한다.
- 날짜가 없는 유효 파일이 전체 실패하지 않는지 확인한다.
- 잘못된 업로드가 기존 데이터와 백업을 덮어쓰지 않는지 확인한다.
- IndexedDB 복원과 localStorage 보기 상태 복원을 테스트한다.
- 생성된 파일이 실제 XLSX 워크북인지 확인한다.

### 화면 검증

- 데스크톱과 작은 화면에서 차트·표·모달이 깨지지 않는지 확인한다.
- 드래그 앤 드롭, 버튼 업로드, 적용 취소, 백업 복원을 직접 수행한다.
- 긴 파일명, 다수 파일, 많은 오류가 있어도 모달 사용이 가능한지 확인한다.
- 고정 헤더와 첫 열이 서로 겹치지 않는지 확인한다.
- 키보드만으로 갱신 모달을 사용할 수 있는지 확인한다.

## 12. 완료 조건

- 사용자가 업로드한 파일의 반영 여부와 실패 원인을 화면에서 확인할 수 있다.
- CSV와 지원 Excel 형식이 날짜 열의 존재 여부와 무관하게 유효한 범위에서 처리된다.
- 오류 파일은 기존 정상 데이터를 훼손하지 않는다.
- 마지막 정상 데이터가 재실행 시 자동 복원된다.
- 사용자가 백업을 내려받고 불러오고 초기화할 수 있다.
- Excel 내보내기 파일이 실제 `.xlsx`로 열린다.
- 표와 차트가 데스크톱·모바일에서 깨지지 않는다.
- 필터와 보기 선택이 다음 실행 때 복원된다.
- 기존 지표 산식, 주차 표기, AF 코드 매칭 동작에 회귀가 없다.

- 운영 메모와 사용자별 협업 기능
- 서버 저장소 및 권한 관리
- AI 기반 이상치 설명
