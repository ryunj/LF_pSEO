# pSEO 실적 대시보드

LF몰 pSEO 페이지의 **유입(PV·UV)** 과 **콘텐츠 운영 상태**를 한 화면에서 보는 정적 대시보드.
HTML 한 장 + 빌드 스크립트. **실적 데이터와 콘텐츠 대장은 이 저장소에 없다.**

## 화면

| 메뉴 | 내용 |
|---|---|
| 실적 대시보드 | 최근 추세(7·14영업일) → 실적 요약 → 흐름 차트 → 기간별 실적 → 차원별 실적 |
| 리스트 관리 | 업로드 현황 타일 · 차수/미반영/브랜드 분포 · 페이지 리스트(컬럼별 필터·정렬) |

- 지표: **유입(PV) · 유입(UV)** — 연결 완료 / 고객수 · 거래액 · 첫구매고객수 · 첫구매거래액 — 자리만 잡아둠
- 기간: 월별 / 주별 / 일별 × 일평균 / 누계, 비교는 **직전 기간**
  (2026년 7월 시작 프로젝트라 전년 데이터가 없다. 1년 쌓이면 전년 비교를 다시 넣는다.)
- 필터: 페이지 유형(브랜드 / 성별×카테고리 / CEP) · 성별 · 브랜드 · 카테고리
- 페이지 리스트는 컬럼 머리글 클릭으로 정렬, 그 아래 칸으로 컬럼별 필터

## 쓰는 법

### 1) 브라우저에서 (개발 없이)

`dashboard.html` 을 열고 파일을 **끌어다 놓거나** 우상단 `데이터 갱신` 으로 고른다. 둘 다 올려도 되고 하나만 올려도 된다.

| 파일 | 알아보는 기준 | 내용 |
|---|---|---|
| 실적 CSV | 헤더에 `YYYYMMDD` 날짜 열 | 행 = `PV`/`UV` × AF코드, 열 = 유입 연월일. 태블로에서 받은 UTF-16 탭 구분 그대로 가능 |
| 콘텐츠 대장 CSV | 헤더에 `AF코드` + `키워드` | `차수 · 키워드 · AF코드 · slug · 현재 운영중 · 업데이트 날짜 · 최신 반영 · 미반영 분류 · 미반영 사유` |
| AF코드 시트 CSV | 헤더에 `매체코드` | 구글시트 `PSEO` 탭 (보조 매핑) |

> xlsx 는 브라우저가 읽지 못한다. 대장은 **CSV 로 저장해서** 올리거나 아래 빌드를 쓴다.

### 2) 로컬 빌드

```bash
pip install -r requirements.txt
python3 build_data.py pSEO_UV.csv pSEO_전체대장_YYYYMMDD.xlsx   # → data.js
```

`data.js` 가 있으면 `dashboard.html` 이 자동으로 읽는다. (`.gitignore` 에 있어 커밋되지 않는다.)

### 3) Streamlit 배포

Streamlit Cloud → New app → Repository `ryunj/LF_pSEO` · Branch `main` · **Main file path `app.py`**.
서버에 데이터가 없으므로 보는 사람이 화면에서 CSV 를 올려 쓴다.

## AF코드 매핑 — 주의

**콘텐츠 대장의 `AF코드 ↔ 키워드` 가 기준이다.**
구글시트 `★PSEOAF_코드_자동화_시트` 의 `PSEO` 탭은 `PSBRD1~500` 구간에서 대장과 이름이 다르다
(자동화시트에서 코드를 다시 채번한 뒤 PSEO 탭이 갱신되지 않은 것으로 보임 — 겹치는 400건 중 10건만 일치).
`PSBRD501` 이후는 두 시트가 서로 일치한다. 대장에 없는 코드는 화면 상단에 건수로 표시된다.

키워드에서 브랜드 · 성별 · 카테고리를 분해한다. 브랜드 사전은 `build_data.py` 의 `BRANDS` 이며
`질스튜어트 뉴욕`, `위크엔드 막스마라`, `질 바이 질스튜어트` 처럼 띄어쓴 이름을 먼저 매칭한다.

## 지표 정의

- 주차는 ISO 월~일
- **일평균 분모 = 적재된 일자 수**. 필터 때문에 유입이 0인 날이 생겨도 분모를 줄이지 않는다
- **UV 는 코드 합산값**이다. 한 사람이 여러 pSEO 페이지를 보면 코드마다 1로 세므로 태블로의 중복제거 총계보다 크다.
  필터를 걸지 않았을 때는 UV 타일에 중복제거 총계를 함께 보여 준다
- 최근 추세 타일의 "최근 N영업일"은 달력 N일이 아니라 **유입이 적재된 날 N개**다

|---|---|
